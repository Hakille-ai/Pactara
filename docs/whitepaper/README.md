# PACTARA Protocol Whitepaper

## Founding Thesis

Internet connected information. PACTARA connects action.

Every meaningful action can be represented through six primitives:

- identity
- intent
- consent
- proof
- value
- execution

The core unit is the PACT: a portable, signed, verifiable, revocable action.

## First Civilization-Scale Goal

Create a protocol that can be used by humans, AI agents, organizations, machines, products, cities, and public institutions without forcing everyone into a single platform.

## First Technical Goal

Make an action verifiable in less than 30 seconds:

1. Create an identity.
2. Create a PACT.
3. Sign it.
4. Verify it.
5. Share it through QR or API.
6. Revoke it if consent changes.

## v0.2 Expansion

The protocol now starts moving beyond contracts into civilization-grade primitives:

- **Genome**: every thing can carry origin, memory, rights, and responsibility.
- **Proof**: every claim can be attached to a verifiable object.
- **Mandate**: every AI action can be bounded by explicit delegated authority.
- **Network Status**: the protocol can observe itself as a living system.

## v0.3 Expansion

PACTARA now starts becoming portable:

- an identity can expose a public DID document
- a PACT can become a bundle that travels outside the API
- every PACT can show a timeline of its protocol life
- every agent mandate can be checked before action

This is the difference between a dashboard and infrastructure: trust can move.

## v0.4 Expansion

PACTARA now starts separating verification from location.

- A PACT Bundle can be verified offline by the `pactara-verifier` crate.
- A verifier no longer needs to trust the API response; it can recompute hash and signature from the bundle itself.
- The protocol can render a Trust Graph across identities, PACTs, proofs, mandates, and genomes.
- The dashboard now shows PACTARA as a living trust network, not only as isolated records.

This is the first step toward phones, edge devices, field inspectors, ports, clinics, agents, and future validators checking PACTARA actions anywhere.

## v0.5 Expansion

PACTARA now becomes an operating layer.

- Domains turn civilization into composable protocol modules.
- Auth moves toward passkeys and client-side sovereignty.
- Ledger and payment intents simulate value flow without touching real money.
- Agents become bounded actors that require mandates and policy.
- Audit events give the system institutional memory.

This is the shift from a protocol console to a civilization runtime: identity, action, value, delegation and accountability now share one substrate.

## v0.6 Expansion

PACTARA now starts becoming operable.

- Readiness makes the runtime checkable by machines before traffic depends on it.
- Mission Control summarizes the living state of the protocol in one operational surface.
- Ledger statements expose credits, debits, and net balance from append-only entries.
- Payment history turns settlement attempts into inspectable protocol objects.
- Agent run history makes delegated autonomy visible after execution.

This is the shift from a working system to an infrastructure system: PACTARA can now be monitored, inspected, and governed while it runs.

## v0.7 Expansion

PACTARA now starts behaving like a sovereign runtime.

- Auth is no longer only a future concern: sessions, credentials, revocation, signed requests, and nonce replay protection are visible protocol surfaces.
- The eight civilization domains now have guided workflows, so economy, knowledge, health consent, governance, energy, link, space, and transport can be operated without writing raw JSON.
- The sandbox ledger can issue internal `PACT`, hold funds in escrow, release holds, reject payments, and post direct double-entry transfers.
- Agents move from simple runs to supervised task queues with mandate checks, policy gates, human approval, and execution logs.
- Policy becomes persistent institutional memory: rules and decisions are separated, auditable, and ordered by conservative precedence.
- Reputation becomes derived trust: signed action, proof, payment, revocation, and audit posture can become a score.
- Search and stream make the runtime feel alive: operators can find objects across the system and watch runtime state through an SSE surface.

This is the shift from infrastructure to an operating layer: PACTARA is no longer only storing verifiable actions; it is coordinating workflows, value, authority, security, and memory through one local-first protocol substrate.

## v0.8 Expansion

PACTARA now starts behaving like a world runtime.

- World scenarios let an operator model shocks across domains as actors, resources, risks, dependencies, and outcomes.
- Scenario runs turn those models into impact scores, risk levels, recommended actions, and generated protocol objects.
- Runtime commands become a higher language for the protocol: an operator can express intent, and PACTARA creates the signed PACT, workflow, risk, audit trail, and next actions.
- Agent crews make delegated intelligence collaborative: multiple agents can be grouped under mandates and policy before they act.
- Civilization signals give the runtime a way to surface operational changes without hiding them inside logs.
- The unified timeline makes PACTARA legible as an operating system: events, actions, workflows, commands, crews, and simulations appear in one chronological surface.

This is the shift from operating layer to intelligence layer: PACTARA can now simulate, command, supervise, and observe civilization-domain activity while keeping PostgreSQL as source of truth and keeping all value flow sandboxed.
